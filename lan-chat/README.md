# Secure Chat LAN

تطبيق محادثات محلي يعمل على نفس شبكة Wi‑Fi/Hotspot باستخدام Node.js وSocket.io. الخادم يدير الحضور والإشارة فقط؛ الرسائل النصية تُشفّر داخل المتصفح باستخدام ECDH P‑256 ثم AES‑GCM، ولا يستطيع الخادم فكها. المكالمات والملفات تنتقل عبر WebRTC DataChannel/MediaStream مباشرة بين الجهازين.

## التشغيل

```bash
cd lan-chat
npm install
npm start
```

المنفذ الافتراضي هو `3100`. يمكن تغييره بشكل صريح عبر `LAN_PORT=3200 npm start`.

ثم افتح `http://localhost:3100` للاختبار على نفس الجهاز. لاختبار جهازين على LAN استخدم عنوان الجهاز الذي يشغل Node.js:

```bash
hostname -I
# افتح http://192.168.x.x:3100 من الجهاز الآخر
```

## شرط التشفير في المتصفح

تتطلب Web Crypto API سياقاً آمناً. `localhost` يعمل عادةً مباشرة، أما عنوان LAN فيحتاج HTTPS بشهادة موثوقة على الجهازين. في بيئة اختبار يمكن تشغيل Chrome مع اعتبار الأصل آمناً، لكن لا تستخدم ذلك في الإنتاج. استخدم شهادة داخلية موثوقة أو reverse proxy HTTPS.

## الحسابات والجلسات

التسجيل محلي داخل ذاكرة الخادم، وكلمات المرور تُخزّن كـ scrypt hash مع salt. عند إعادة تشغيل Node.js تُحذف الحسابات لأن هذا مثال LAN بسيط؛ استخدم SQLite/Argon2 وقاعدة بيانات محلية عند الحاجة. الجلسة token في ذاكرة الخادم وتنتهي خلال 12 ساعة.

## WebRTC

لا توجد خوادم STUN/TURN في الإعداد لأن الهدف شبكة LAN دون إنترنت. إذا كانت الشبكة تمنع الاتصال المباشر أو كان الطرفان خلف NAT مختلف، ستحتاج STUN/TURN. signaling يمر عبر Socket.io لكنه لا يرى محتوى المكالمة أو الملف.

## الصوت والملفات

زر التسجيل يستخدم MediaRecorder، ثم يرسل التسجيل عبر WebRTC DataChannel. الملفات لا تُرفع إلى الخادم؛ يتم تقسيمها إلى chunks ونقلها مباشرة. يجب إبقاء حجم الملفات مناسباً للذاكرة، وإضافة backpressure وresume قبل الاستخدام الإنتاجي.

## Bluetooth وHotspot

Web Bluetooth لا يملك صلاحية عامة لتشغيل Hotspot أو إدارة Wi‑Fi، كما أنه يعمل فقط في متصفحات محددة وبسياق HTTPS/localhost وبعد تفاعل المستخدم. زر Bluetooth في الواجهة يطلب جهازاً عبر `navigator.bluetooth.requestDevice` كاختبار حقيقي للـ API، لكنه لا يحوّل Bluetooth إلى ناقل Socket.io. التحكم الحقيقي في Hotspot، Bluetooth discovery، الخلفية، والصلاحيات يتطلب تطبيق Android أصلياً (Kotlin/React Native native module). أفضل تصميم عملي هو تشغيل هذا الخادم على الجهاز المضيف عبر Hotspot ثم اتصال المتصفحات بعنوان LAN.

## ملاحظات إنتاجية

- استخدم HTTPS وشهادة موثوقة.
- استبدل تخزين المستخدمين في الذاكرة بقاعدة محلية.
- أضف rate limiting وCSRF وحماية من brute force.
- اعرض بصمة المفتاح العام للمستخدمين مع تحقق خارج القناة.
- أضف توقيعاً/تدويراً للمفاتيح وإدارة الأجهزة.
- أضف backpressure وchecksum للملفات الكبيرة.
